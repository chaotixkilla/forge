A skill executed by a language model is not a deterministic function: the same version over the same scenario can grade well on one run and stumble on the next, because the executor's phrasing, ordering, and small judgment calls shift run to run. That nondeterminism is the whole reason this rule exists. A single run of the changed arm against a single run of the baseline is an anecdote — the observed difference could be the change doing its work, or it could be the two runs landing on different sides of ordinary jitter, and from one pair you cannot tell which. Every bar below exists to separate a real shift from that jitter, and each is pinned to a concrete value with the reason it sits where it does, because a bar left to the executor's in-the-moment judgment is exactly the noise it was meant to filter.

## Repeats are mandatory: default 3 per arm

Run each arm — the changed tree and the baseline tree — over the same scenario **at least 3 times**, and treat that as the default whenever the caller doesn't say otherwise. Three is the pinned floor for a reason: one run gives a point with no sense of scatter, and two give a difference with no sense of whether that difference is typical or a fluke — you cannot separate signal from noise with a sample that can't express noise. Three runs is the smallest sample that yields both a center (where the arm typically lands) and a spread (how far it wanders), which is precisely the pair of quantities the delta bar below consumes. It is deliberately cheap: benchmark is the heavyweight tier and every repeat costs a full dogfood pass on that arm, so the default buys the minimum statistic that makes the comparison honest and stops there rather than paying for precision the verdict doesn't need.

The floor is a floor, not a ceiling. A skill whose outcomes swing widely run to run produces a spread so wide that three samples locate its center only loosely, and there the caller raises the count — the variance knob is exposed as `--repeats` for exactly this. Raise it when a first pass shows the arms overlapping heavily and you need a tighter read to tell them apart; the reason to override is always observed noise, never a hunch, and the raised count applies to both arms equally so the two remain comparable. Never drop below three: a two-run or one-run benchmark cannot compute the spread the next section requires, so it isn't a cheaper benchmark, it's a broken one.

## The delta bar is relative to spread, never absolute

A per-scenario difference between the arms counts as a **real change only when it exceeds the run-to-run spread of the arms themselves** — the difference in centers must be larger than the scatter within each arm before you may call it signal. Refuse the tempting shortcut of an absolute threshold ("a change of N points is real"): what counts as a large difference is meaningless in the abstract, because the run-to-run noise varies enormously by skill — a stable skill barely wanders between runs, so a small center shift is plainly real, while a noisy skill wanders so far that the same small shift is indistinguishable from jitter. An absolute bar is therefore either too loose for the stable skill or too strict for the noisy one, and wrong for almost every skill in between. Measuring the difference against each arm's own observed spread is self-calibrating — the bar tightens automatically for quiet skills and loosens for turbulent ones — and it is defensible on its face, because it asks the only question that matters: is the gap between the versions bigger than the gap the same version shows against itself? When the between-arm difference sits inside that within-arm scatter, the two versions are statistically indistinguishable on that scenario no matter how large the raw number looks.

This is why the repeats and the delta bar are one mechanism, not two: the repeats exist to measure the spread, and the spread is what the delta is judged against. Cut the repeats and you have no spread; with no spread you have no bar, and every difference collapses back into an absolute number read on a hunch.

## A within-noise delta is reported as no measurable change

State the consequence plainly and hold to it. When a scenario's between-arm delta does not clear its spread, the finding is **"no measurable change"** — and that scenario is never presented as a win, an improvement, or a regression, in whichever direction the raw number happened to lean. A difference the method cannot distinguish from jitter is not a small real effect awaiting a generous reading; it is the absence of demonstrated effect, and reporting it as anything more launders noise into a claim the evidence doesn't support. This restraint is what earns the verdict its weight: benchmark surfaces regressions first and asserts improvements sparingly, and both of those depend on the discipline of calling an indistinguishable delta exactly what it is. Reserve "improvement" and "regression" for the scenarios where the shift clears the bar; everything else is honestly, and usefully, no measurable change.

## When there is no variance to measure

Some skills are effectively deterministic on a given scenario, or carry only file-rooted defects — a leak, an open bar — that grade the same band on every run. Their arms show a run-to-run spread of zero, and there the repeats measure nothing: the delta-vs-spread bar reduces to "is there any band difference at all," and the comparison is doing the work of a **comparative static audit** — running the critics on both versions and diffing the findings. That is still a real, useful result; it catches exactly the file-rooted regressions such skills have, and the differential verdict (improvement / regression / net) stands on its own. But be honest about what the repeats bought: a spread of zero is *no variance the run could resolve at the band granularity*, not a proof of stability, and on a skill whose defects are all file-rooted the Nth run tells you nothing the first two didn't.

The variance machinery — the whole reason this tier runs N times per arm rather than once — earns its heavyweight cost only where a skill's outcome genuinely wanders run to run at the band level: an under-pinned judgment that different cold executors resolve into different bands, an intermittent stall. Spend the full repeat count when you have reason to expect that wander; when a first pass shows spread zero on every scenario, further repeats will too, and you are paying for a comparative audit wearing a heavier coat. This does not weaken the verdict — a regression caught by a comparative audit is still a caught regression — it just tells you when the repeats are load-bearing and when they are ceremony.
