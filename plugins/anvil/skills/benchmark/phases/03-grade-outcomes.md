A run log is a transcript, not a verdict. Phase 02 handed you, for each scenario, a stack of run logs on the changed arm and a stack on the baseline arm — but raw logs can't be compared: two runs of the same scenario differ, and a wall of prose can't be aggregated across repeats or diffed between arms. This phase reduces each run to a graded outcome on a fixed scale, produced by a grader that cannot be swayed by which arm it is looking at. Everything the regression check depends on rides on that last clause: benchmark earns its cost only by catching a change that fixes scenario A while silently breaking scenario B, and that catch is real only if the baseline is graded exactly as hard as the change. Grade the change more gently than its baseline and you have manufactured a win that isn't there.

## Split each run: contract-gradable vs subjective residue

For every run in every arm, split the outcome into two slices. The **contract-gradable slice** is everything the kit's critics can check objectively — whether the run converged, honored the skill's contract, stayed free of tool leaks, held its pinned bars, earned its structure, and respected the ships boundary. The **subjective residue** is the softer part no critic's lens formalizes: the felt clarity of the output, its taste, whether a reader would call it good beyond whether it is correct. Where that line falls — what belongs to the objective grader and what is genuine residue — is not yours to redraw per run; it is pinned in [grading-the-ungradable](../rules/grading-the-ungradable.md). Apply that rule's cut identically to both arms, so the two arms are always split at the same seam.

## Grade the contract slice with the concern-matched critics

The contract slice is graded by anvil's own critics, recruited as the objective assertion library rather than a fresh judge. The six critics and the contract concern each one's charter covers are pinned in [grading-the-ungradable](../rules/grading-the-ungradable.md) — read the roster there rather than re-deriving it. What this phase owns is the *recruiting* — which of those critics to turn on for a scenario — and it is pinned so two graders land on the same roster: **run the full roster by default, and drop a critic only when you can state positively that the change cannot reach its concern at all.** grading-the-ungradable keys each critic to a concern, so an exclusion is a defensible claim ("this diff cannot touch packaging, so the boundary-keeper is off"), not a hunch. The bias toward inclusion is deliberate and, under the band rule below, nearly free: a critic that finds nothing cannot move the worst-finding band, so an extra critic costs a little time and never distorts the grade — while a critic wrongly dropped is a missed regression. When you cannot state the unreachability, keep the critic in.

Give each recruited critic two inputs: the arm's own skill files and that arm's run logs. The diff between the arms is a third input, but only to orient — it tells the critics where the change landed so their reading concentrates there. This is why the default is the full roster and exclusion must be earned: a silent regression most often surfaces in a concern the diff didn't obviously touch, so a roster pruned tight to the changed lines is exactly how the killer regression slips past. A change that reworded one threshold looks like a standards-and-cold-executor job, but if the rewording quietly shifted a step's altitude, only the scaffolding-skeptic catches the rot.

One scoping rule the per-scenario comparison depends on, kept separate from the roster breadth above: **a finding moves a run's band only if it is rooted in a file that run actually exercised.** A scenario drives one path through the skill — the phases, and any guides or branches its inputs reach — and its band must reflect *that path*. Otherwise a defect in a branch the scenario never touched would drag its band, and a change that fixed one path while breaking another — the exact trade this skill exists to catch — would collapse into one undifferentiated grade across every scenario. So attribute each file-rooted finding to the scenarios whose runs exercised its file. This is emphatically **not** license to let a changed path go ungraded — but the remedy is not a bandless finding the verdict has no way to weigh. A changed file that *no* scenario exercised has no run to grade (you never drove that path), so it is not a finding at all: it is a **corpus gap**, the completeness failure phase 01 and [scenario-corpus-discipline](../rules/scenario-corpus-discipline.md) require you to close *before* trusting a verdict. Handle it there, not here: stop, report that the change touches a path the scenario set never covers, widen the corpus to exercise it, and re-run — the same route [04-aggregate-and-decide](04-aggregate-and-decide.md) takes for a scenario that discriminates nothing. That preserves the roster-breadth guarantee — no changed concern goes silently unmeasured — without minting a finding the pipeline has no channel for: the fix for an unexercised change is a better corpus, not a guessed band. Scope the *band* to the exercised path; close the *gap* by completing the corpus.

## Reduce each run to a verdict on the pinned band

The critics return findings; the run's grade is the single band its worst surviving finding lands in. Land each finding at the disposition **its own critic or audit already assigns it** — do not re-judge its bite. A critic states that disposition directly (leak-hunter's *confirmed* vs *suspected*, scaffolding-skeptic's *cut* vs *merge-candidate*, boundary-keeper's *certain* vs *borderline*; the cold-executor and standards-skeptic surface only blocking findings). An audit states it as a **tier**: [audit-contract](../../audit-contract/SKILL.md) ranks findings *method-loss* → *behavior-breaker* → *caller-docs* → *convention-defect* → no-action notes, on its own pinned rule that "changes what executes outranks changes what a reader understands"; [audit-tool-leaks](../../audit-tool-leaks/SKILL.md) and [audit-packaging](../../audit-packaging/SKILL.md) mark confirmed defects apart from borderline ones. Read the stated disposition or tier — don't re-grade it. That is what makes the band converge: a disposition or tier is a call the critic or audit already made and two graders read the same, whereas "how much does it bite" is a feeling that drifts.

The four bands follow from the worst finding's disposition, plus one objective test — **did the run produce a usable result at all?**

- **clean** — the run produced a usable result, and no critic or audit raised a finding at all: everything they saw, they passed or filed only as a trailing no-action note.
- **minor** — the run produced a usable result and honored its executing contract; the worst finding is one raised **without a blocking disposition** — a critic's *suspected / borderline / merge-candidate*, or an audit-contract *caller-docs* or *convention-defect* finding (its own "runs correctly today" tiers, which change what a reader understands, not what executes — a misfiled slot lands here).
- **degraded** — the run produced a usable result, but a critic or audit raised a **blocking** finding on the arm: a violated or open bar, a confirmed tool leak, a confirmed ships-boundary or packaging breach, structure that no longer earns its place, a cold-executor convergence defect (a step two cold executors would resolve differently), or an audit-contract *method-loss* or *behavior-breaker* finding (its tiers that change what executes). The band asks only *whether* such a finding exists on the arm; it never ranks the findings against each other.
- **broken** — the run could not complete, or produced no usable result: it stalled where a cold executor could not proceed; or its deliverable is absent, truncated, or unusable — for an artifact output, one that fails to load (frontmatter that won't parse, a structurally invalid file); for a prose output (a report, a review, a findings set — what anvil's own diagnostic skills produce), a result from which **not one finding or claim can be acted on** without going back and redoing the work — the prose analog of "won't parse." A merely rambling or partly self-contradictory result that still yields at least one actionable claim is *usable but flawed*: degraded, not broken. And a run that stalled on a step it could not perform is broken even if it emitted *something* in place of the real deliverable — an improvised substitute for a mandated step the skill required is the stall's symptom, not a usable result. The usable-result test asks whether the skill's own procedure produced its deliverable, not whether some string came back. The **usable-result test** runs first, before any finding is weighed, and is what separates broken from degraded: a result you can't use is not a worse grade, it is the absence of one; a result you *can* use but that carries a blocking finding is degraded.

Four bands, coarser than a free-form numeric score on purpose — convergence is the whole point of grading with an assertion library — yet fine enough that one full band of movement between arms is a candidate signal a single nit can't fake. The band is not the decision; how many bands of movement, across how many repeats, counts as real rather than jitter belongs to [signal-vs-noise](../rules/signal-vs-noise.md), which phase 04 applies. Your job ends at a defensible per-run band. (An *open bar* is the case that looks like it might not land — no threshold was *violated*, since there was none to cross — but the standards-skeptic fails the gate on it, so it is a blocking finding: **degraded**, every run.)

Tag each finding by where it is rooted — and rootedness follows the finding's *cause*, not its surface. A cause in the arm's *files* — a leak in the changed tree, a flag with no module, a mandated step the files make impossible — is constant across every run of that arm *that exercises the file* and shifts those runs' band the same way each time, even when the *symptom* is a per-run stall. A cause in a *specific run's* nondeterminism — a guess this run happened to make, a stall only this run hit by unlucky wandering — is that run's alone and varies run to run. So a stall every run hits because the files demand the impossible is file-rooted (constant); a stall one run hit and the next didn't is run-rooted. The varying slice is precisely why repeats exist; the constant slice is a fixed offset. Keep the tag so phase 04 doesn't average a constant as though it jittered.

## Grade the subjective residue with a blind reading, and mark it soft

Only for the residue no recruited critic covers, fall back to a reading you perform yourself — there is no separate judge agent to recruit. You drove both arms, so you already know which stack is the change and true blindness is impossible; approximate it deliberately — strip the arm labels, put the two outputs in a fixed order that does not encode which is newer, and score toward neither — and treat the residue as the soft signal that imperfection makes it. Score on the *one* residue dimension the diff most plausibly moved — clarity, or smoothness, or taste, whichever the change actually touched — and name that dimension, so two runs judge on the same axis rather than drifting across all three. Run it under the single-rubric discipline [grading-the-ungradable](../rules/grading-the-ungradable.md) pins, which fixes the answer's shape: a forced arm-A / arm-B / tie preference with a one-line basis, never a number. What this phase adds is the handoff: carry that reading's output as an explicitly *soft* signal, separate from the contract band and never folded into it, so phase 04 stays free to weight it below the contract grade or set it aside when the two disagree.

## Grade both arms with one rubric

The fairness discipline is the load-bearing wall of this phase, and it reaches wider than the judge: the same critic roster, the same four-band ladder, and the same subjective question all apply to both arms, arm-blind wherever the input allows it — grade a scenario's runs without knowing which stack is the change, so arm identity cannot tilt a call. Because the contract band is derived mechanically from critic findings, arm-blindness there is close to free — the rubric leaves no seam for generosity to enter. Any asymmetry you introduce doesn't make the change look good; it makes the comparison lie, and a lying comparison is worse than no benchmark at all.

Hand phase 04, for each scenario, both arms' stacks of per-run bands — each band tagged with its file-rooted vs run-rooted findings and its soft subjective note — ready to aggregate across repeats with variance in [04-aggregate-and-decide](04-aggregate-and-decide.md).
