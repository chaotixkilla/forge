A skill's wiring can be perfectly conformant and two runs of it still disagree — because contracts break in content, too. Wherever a skill makes or demands a judgment without fixing the bar, each executor fills the gap from its own priors, priors regress to average practice, and the skill degrades silently on every run with nothing crashing. This rule is the content-level contract the cross-reference phase checks: every standard-point closed. It defines what closure *is* and how to check it; it never says what any particular bar should be.

## What a standard-point is

Any place a skill's content makes or demands a judgment two competent cold executors could resolve differently: a bar for "good enough," a threshold that admits or rejects a candidate, a grade or rank the output carries, a criterion for selecting among alternatives. Most have a mechanical shape you check by inspection — the two groups below, run first. A genuinely judgment-y residue takes the divergence-pair test at the end.

## The defined-output closure checklist

When a skill's output *carries a defined shape*, that shape owes closure. Run the checklist below against every output a skill emits or relays; each missing element is nameable by inspection, so a finding here is one no auditor can wave through:

- **Graded scale.** The trigger is the *output*, not the wording: if the skill's findings or candidates carry a **grade, rating, severity, confidence, or rank at all**, a named scale is mandatory, and each level must carry a one-clause **assignment test** (the condition that lands a case on that rung), inline or in a cited rule, with a concrete anchor on the top and bottom levels drawn from the class the skill grades. Two dodges are the *same* finding: **rating the output while naming no scale** ("assign by impact" with no rungs — every executor invents the ladder), and **naming the rungs without an assignment test** (bare labels like `major`/`minor` — every executor draws the lines differently). File one finding per undefined level, or one against the whole scale when the output is rated but carries no defined scale at all.
- **Relayed vocabulary.** When the skill *aggregates* — its output relays a grade or label emitted by a sub-agent or sub-skill — the pinned shape must reproduce that component's *full* defined vocabulary, or pin the collapse rule. Diff the relayed field's enumerated values against the source's scale; a missing value is a finding, because the aggregator will silently drop or coerce it — overstating confidence exactly where it should carry it forward.
- **Ratio or threshold.** When a bar is a ratio, a percentage, or a numeric cut, a single number is not closure — pin **all four** of {the threshold value, the numerator, the denominator/base, and the unit it is measured in} in one pass, or the bar re-opens one parameter at a time across re-verify rounds (the threshold converges, then the unit it is counted in, then the base it is a fraction of). Finding: a ratio or threshold bar missing any of the four.
- **Outcome partition.** When an output *classifies the whole run* into one of an enumerated set of terminal outcomes — a verdict, a disposition, the result the run resolves to — the enum owes more than a per-value assignment test, it owes a **partition proof**: every reachable run lands in *exactly one* value (exhaustive — none falls outside the set; mutually exclusive — none satisfies two). A per-value rubric proves each value is *reachable*; only the partition proves the set is *complete*. A **two-value** outcome (pass/fail, accept/reject) is the specific tell — "indeterminate / can't-tell / not-yet-established" is so often a real third outcome that a binary verdict should be challenged to name the run that lands between its two values; if such a run exists, the enum is short a value and silently forces those runs onto the wrong side. Distinguish this from a graded scale: a scale's rungs are ordered points on a ladder and you check each has an assignment test, whereas an outcome enum's values may be unordered and you additionally check they *tile the whole outcome space*. Finding: a terminal outcome enum with no exhaustiveness/mutual-exclusivity proof, or a two-value verdict with a reachable run its two values don't cover.
- **Absence / negative case.** A graded or classified output usually carries rungs only for a *positive* finding — how strong a source is, how sure a claim is, how severe a defect — and none for the honest **negative**: a well-founded absence, none-found, confirmed-clean. The output owes a *recorded* decision on where the negative lands — a **level** on the scale, a **distinct terminal outcome**, or the **empty case** (no output owed) — and, exactly like open-by-design, that decision counts only when it is *visible in the text*: bare silence about the negative is the omission this check catches, not a tacit empty case. Do not assume the negative is self-evidently the bottom rung: a *confirmed* absence (a definitive "no such study exists," a verified "the control is absent") can be the *strongest* thing the run says, so treating absence as the floor is a decision to defend, not a default. Finding: a graded or classified output with no recorded treatment of its negative/absence case. `(basis: dogfood DR4 — graded scales built for positive claims under-specified a documented absence, and two cold runs split on its top-line grade; recurs cross-skill, e.g. a security review's confirmed-absent control.)`

One more shape belongs in this checklist — a structural smell that reads as closed and isn't, run against **every single-entity classification a skill makes, whether or not the outcome-partition check fired**: a **classification that is really a relation**. When a bar classifies a *single* entity ("is this branch a release-line or an intermediate?") but the decision it feeds actually turns on *two* entities in relation ("does *this environment* deploy from *this branch*?"), the classification is a latent contradiction — the moment the two entities' natural categories overlap, one entity lands in two classes at once and two cold runs split on it. The tell: a label on entity A is used to decide something about A's *interaction* with B. Flag it open-by-omission and state the closure — read the **relation** (a per-`(A, B)` lookup with a stated method), not a property of A alone. It resolves the way a re-opening partition determinant does: stop labelling one entity and decompose to the primitive relation the decision truly turns on.

## Two checks on any pinned bar

These apply to a bar whatever its output shape — a graded rung, a threshold, or a one-off "good enough" line:

- **Sourced bar.** Every bar a skill *pins* carries, inline, exactly one visible marker: **`(basis: <the authority or derivation the bar rests on>)`** — the design record, the convention it mirrors, the failure it prevents — or **`(routed to maintainer: <the derived proposal and why>)`** when no accountable source settled it and the pin is a proposal awaiting the maintainer's call. **Finding: a pinned bar carrying neither marker** — a fiat assertion, a tightness that came from nowhere the next editor can trace or contest. Check by inspection: find the pins, confirm each carries one marker.
- **Discriminator-linked judgment.** Every grading, ranking, or selection verb — "grade," "prioritize," "pick the strongest," "keep the good ones," "filter," "rank by" — must have its **discriminator** (the property the judgment turns on) stated inline or in a cited rule the verb can reach. A method pins as well as a number: "weigh candidates by <named factors>, prefer the one that <discriminator>" is closed though nothing in it is numeric. **Finding: a judgment verb with no reachable discriminator** — the executor invents the axis, and two runs rank on different ones.

## The two closed states, and the defect

A standard-point is closed when it is either:

- **Pinned** — stated precisely enough that two cold executors reach the same verdict on a borderline case, carrying its `(basis: …)` or `(routed to maintainer: …)` marker (the sourced-bar check). The test for "precisely enough": construct a borderline case for the class the skill judges (a candidate sitting at the threshold; an input straddling a window's edge). If the page's words leave one defensible verdict, pinned; if two survive, not pinned, however confident the sentence.
- **Open-by-design** — deliberately left to executor or context judgment, with the reason recorded inline ("deliberately open: pinning this would be false precision because …"). The recorded reason is what separates a decision from an omission.

The defect is **open by omission**: a bar neither pinned-with-a-marker nor open-with-a-reason. Nobody decided to leave it open, so every executor closes it alone — silently, differently, from priors. The checklists above catch its common shapes — the undefined scale rung, the unpinned ratio parameter, the missing absence case, the fiat pin, the discriminator-less verb; the residue test below catches the rest.

## The residue: divergence-pair proof

A judgment can pass every check above and still be open — a bare qualifier ("appropriate," "sensible," "significant," "sufficient," "too long") standing where a bar should be, attached to no scale, no explicit pin, no grading verb. For that residue the discriminator against noise is the **divergence pair**: write the two defensible cold readings a competent executor would each produce. If you can write the second reading, the point is open by omission — file it with the pair as proof. If you cannot, it converges on its own; don't file it.

## What the audit does with an open point

Flag it; never fill it. The finding quotes the judgment demanded and states the expected closure — define the undefined level, add the missing `(basis: …)` / `(routed to maintainer: …)` marker to the fiat pin, supply the discriminator-less verb its axis, or record inline why the bar stays open. Proposing the bar's value from the auditor's own sense of "good" reproduces the defect inside the audit: the value belongs to the maintainer, sourced from the plugin's design record or the authority the skill's domain answers to. Even the `(routed to maintainer: …)` marker is the *producer's* proposal, written when the skill was; the audit confirms a marker is present, it never authors the bar or its basis.
