# Skip-resistance

The load-wiring check ([03-cross-reference](../phases/03-cross-reference.md)) confirms every phase is *referenced*, so it *can* load. This rule covers the next failure: the phase is referenced, but the running agent never *opens* it — because the spine gloss reads as a complete instruction, or a delegation reads as work to perform in place. The harness loads a phase or a sibling skill only when the agent opens or invokes it, so wiring runs the method only when it is **load-bearing**: the spine cannot be acted on without opening the phase, and a delegation cannot be satisfied without invoking the sibling. *Advisory* wiring — a self-sufficient gloss, a "delegates to X" that reads as "do X's job yourself" — lets the agent act on the summary, and the method never runs. Two statically-checkable properties keep wiring load-bearing.

## The spine gloss is a pointer, not an instruction

A numbered SKILL.md line names *what* the step achieves and points at its phase; it does not carry the method to *do* it. The test: **could a cold executor complete the step from the spine line alone?** If yes, the method has leaked up into the spine and the phase file will be skipped. Conformant — a capability plus a trailing pointer to the phase. Non-conformant — a runnable procedure sitting on the spine line. (Exempt: a thin/port skill whose spine *is* an inline procedure with no `phases/` — there is nothing to skip to; its spine is the method by design.)

## A delegation is a named invocation, not a description

A phase that hands a capability to a sibling skill or port names the sibling to **invoke** and consumes its returned result — it never describes the work as something to perform in place. The test: **does the step read as "invoke X and use what it returns," or as "do the thing X does"?** The latter licenses a raw, hand-rolled substitute — the delegation-bypass. A conformant delegation cites the sibling's `SKILL.md` (per the load-wiring citation form) and treats the returned result as the next step's input.

## A load-bearing rule citation is a dependency, not an aside

The two properties above govern the spine and the delegation seam. The third seam is `phases/` → `rules/`, and it fails differently, because a rule citation carries no inherent obligation: a phase cites a rule and the executor decides whether to open it. That decision is made on the citation's *phrasing*, and the house form — a trailing parenthetical, `([name](../rules/name.md))` — reads as optional depth. For most rules that is correct and desirable. For some it silently drops the standard.

The discriminator is what the cited file *holds*, and every rule citation is one of two registers:

- **Depth-on-demand.** The phase states the method inline; the rule adds calibration, rationale, or edge cases. A cold executor that never opens it still does the step *correctly* — it just does it with less confidence. The parenthetical form is right, and the file is correctly optional. This is the majority, and making these mandatory reads is how a skill's load path bloats.
- **Load-bearing.** The step's output must conform to something **defined only in the cited file** — a scale's levels, a defined vocabulary or taxonomy, a pinned threshold, a named set the output must draw from. Here a cold executor that skips the file does not do the step with less confidence; it does a *different* step, filling the scale from its priors. That is the silent fill the standards lens exists to prevent, reintroduced at the load layer after the bar was properly pinned.

So the test is not "is this rule important" — it is: **can the step be completed correctly without the file?** Where the answer is no, the citation must be phrased so that acting without opening it is visibly impossible. The conformant form names *what it needs from the file* rather than merely pointing at it: `grade on the five levels defined in [the scale](../rules/<scale>.md)` cannot be satisfied by an executor that never learned the five levels, whereas `grade the finding ([the scale](../rules/<scale>.md))` can be, and will be. Non-conformant — a step that grades, ranks, selects, filters, or classifies, whose discriminator lives only in a cited rule, and whose citation is a bare trailing parenthetical.

## Where a skip is correct, license it explicitly

The property above has an obvious failure mode if applied alone: an author who wants to be safe marks every citation load-bearing, and the skill becomes a mandatory read of its whole library — trading a dropped standard for the eager-loading defect, which costs every run instead of some. The counterweight is that a phase may **license a skip, with its condition named**. A stated "skip X when Y" is a decision the executor can act on; an unstated one is a guess it makes anyway. Two forms carry it: a firing condition attached to the citation itself (the reader knows whether this rule is in play before opening it), and an explicit escape at the step ("if the change touches no external boundary, this step is a no-op — say so and move on").

The asymmetry is deliberate: a load-bearing citation that reads optional loses the standard *silently*, while an optional citation that reads mandatory only costs tokens *visibly*. So where the register is genuinely unclear, phrase it load-bearing and let the load-path audit argue back with a measurement — that is a resolvable disagreement between two checks, not a defect that ships.

## What the check flags

Statically, off the files: the three findings above — a spine gloss that carries method (not a pointer), a delegation phrased as work-to-do (not a named invocation), and a load-bearing rule citation phrased as an aside (a grading/ranking/selecting/classifying step whose discriminator exists only in a rule it cites parenthetically). The third is scoped to what is decidable on the page: the citing sentence demands a conforming output, and the conforming vocabulary appears in the cited file and not in the citing one. Where the discriminator is stated *inline as well*, the citation is depth-on-demand by construction and is not a finding.

**Not** checked: whether a phase carries a *completion trace* (a named output a later step verifies) — not statically decidable, so it is codify's authoring discipline, not an audit join. Also not checked here: whether the *volume* a citation makes reachable is proportionate. This rule asks whether the necessary loads will happen; whether the happening loads are necessary is the load-path audit's question, and the two are deliberately separate checks that can disagree.

`(basis: derived — from the harness load model (a referenced file runs only when opened/invoked) and the dogfood record, where every phase-skip and delegation-bypass traced to a gloss or delegation that read as self-sufficient. The rule-citation register extends the same load model one seam further, on the maintainer's field report that phases and rules whose names read skippable get skipped in practice — to the point of needing session-level "don't skip the rules" prompting, which is the symptom of a load-bearing dependency phrased as an aside. The conformant form mirrors the pattern in the harness's own shipped skills, which state a read-ordering imperative ("read this before X"), attach each reference to the branch that fires it rather than to a roster, and name the rationalization a reader would skip on. (basis: context-engineering alignment pass, 2026-07-26.))`
