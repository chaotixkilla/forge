Each *act* item now carries a tier; this phase turns that tier into the actual change, by handing the item to the engine that owns its mechanism — or, for the one tier revise owns, making the edit itself. The governing discipline is **delegate, don't re-implement**: revise is an orchestrator, and every method edit, every new component, every piece of structure is some other skill's job. revise's own hands touch exactly one thing — wiring — and everything else is dispatched. Blur that and revise stops being a lean router and becomes a second, worse copy of codify.

## Route each item by its tier

- **T1 → edit directly.** This is the only tier revise fixes with its own tools, and it fixes **wiring only**: insert a resolvable citation link into the phase that should reach an existing rule (of the form `[<rule>](../rules/<rule>.md)`), declare an activating flag for an existing module, repair a dangling or bare-backtick link. Never a step's procedure, a judgment bar, a default, or a scale — those are method, and method is T2. If a "T1" edit finds itself rewording a sentence of method, it was mis-sized: stop and return it to [03-size-intervention](03-size-intervention.md).
- **T2 → dispatch to [codify](../../codify/SKILL.md)** (its regenerate lane): hand it the target `--plugin` and `--skill` and the specific standard-point to close; codify authors the method and writes the `(basis:)` marker. revise supplies both required inputs and never lets codify guess the target, and never hand-writes the clause itself. Dispatch **once per (skill, standard-point)**: a clustered item whose locations span two skills dispatches once per skill, since codify takes a single `--skill`.
- **T3 → dispatch to [add-component](../../add-component/SKILL.md)**: hand it the `--plugin`, `--kind`, `--name` (and `--skill` for a skill-scoped kind). It inherits add-component's kind→home resolution, clobber guard, and port-and-adapter seam guard — which may correctly return "delegate to an existing port, no new file," in which case the item collapses to a T1/T2, not a new component. When a new rule is created, revise then performs the **T1 follow-through**: add the citing link from each consuming phase, since add-component leaves that to the caller.
- **T4 → route out.** Do not invoke a builder. Report the structural gap with its recommended target ([scaffold-skill](../../scaffold-skill/SKILL.md) or new-plugin) and the reason, for the **maintainer** to run; then hand the filled structure to codify. Birthing or splitting structure is a pool-architecture judgment revise does not own (ratified 2026-07-13) — auto-building it is precisely how a bloat-prevention skill would start creating speculative structure.

## The scope guard

Every file revise touches — directly (T1) or through a dispatched engine — must **map back to a specific item** in the worklist. Before finishing, walk the diff: any edited file that traces to no item is an unmapped "while I was here" change and is **reverted**. revise fixes the batch and only the batch; opportunistic cleanups belong in their own batch with their own findings. A provisional route from intake or triage may be **diverged from** when sizing revealed a better owner — but the divergence is recorded with its reason for the phase-05 report, never silent.

## Under --dry-run

Under `--dry-run` the run **stops at the top of this phase** and invokes no engine and writes nothing. Report the sized change set that *would* apply — each item with its disposition, tier, target engine, and (if any) climb-reason — as an explicitly **unverified** preview: because no change is made, no diff exists, and [05-verify-and-report](05-verify-and-report.md) does not run.
