A batch arrives in more than one shape — a diagnostic report, a maintainer's written change-request, a line of freeform feedback — and the later phases (triage, sizing, dispatch) can only work on a uniform worklist. This phase normalizes whatever came in into one comparable set of **actionable items**, so nothing downstream has to branch on where an item originated. Get it wrong and two failures follow: a non-work-item (a coverage note, a demoted observation) rides into the worklist as if it were a defect, or a real piece of feedback is dropped because no one raised it to a shape the pipeline can act on.

## The actionability bar

Every item that leaves this phase carries four parts, because triage and sizing both assume them: a **defect** (what is wrong, in one line), a **pointer** (the file/slot/step it lives in — as precise as the source allows), **evidence** (why it's real: the failing case, the cited authority, or the maintainer's stated cost), and a **route** (a *provisional* dispatch key — which engine likely owns the fix; triage and sizing may override it). An item that cannot be raised to all four is **not yet actionable** — name it as such and set it aside; do not invent a pointer or manufacture evidence to force it through.

Beyond the four parts, each item also carries a **grade** for ranking — the bite level [dogfood](../../dogfood/SKILL.md) uses (blocker / friction / nit). A dogfood item arrives with its own; for a change-request or freeform item, **assign one here on that same ladder**, from the cost the item states. Grading happens *here*, once, so triage can order a mixed batch on one scale and never has to invent or re-feel one. dogfood's rungs are anchored to run-behavior (does a cold run halt / diverge / stay identical); a maintainer cost with **no run-behavioral effect** — a readability or maintenance burden, like the bloat this skill was born from — grades by the urgency the maintainer expresses: must-fix → blocker, should-fix → friction, optional → nit. When such a cost expresses **no** urgency and none can be obtained (a bare cost on the `--from` frozen path, no maintainer to ask), default to **friction** and note it was defaulted — the grade only *orders* the worklist and `act` is the default, so a defaulted middle rung mis-orders by at most one rung and never changes what gets done; when the maintainer is reachable, ask rather than default.

## Normalize each input shape to the bar

- **A diagnostic (dogfood) report.** Pull **only** the items under its "Findings ranked by bite" sublists. A real report is multi-run, so expect several such sublists — take them all. **Exclude** everything that is not a work item: coverage/process notes, demoted "not findings," "what worked," and the global "not yet exercised" section. These already carry the four parts; keep dogfood's grade for ranking in the next phase. Do not re-derive dogfood's own actionability standard — this bar is dogfood's; reference it, don't re-implement it (see [dogfood](../../dogfood/SKILL.md)).
- **A maintainer change-request** (Problem / Desired / Scope / Merit, as a review report or notes file supplies). It states the defect (Problem), evidence (Merit), and often a pointer (Scope), but arrives **un-graded** — assign its grade here, on dogfood's ladder, from the cost stated in Merit. If it names a provisional route, keep it; if not, leave the route open for sizing to settle.
- **Freeform feedback** (a sentence, a comment — "this is piling on bloat," "severity isn't scannable"). This is the shape that needs work: locate *what it is about* (the skill, phase, or output it refers to) to supply the pointer, read the defect and its cost as the evidence, and raise it to the bar. This is a **judgment** step — the executor decides what concrete defect the feedback names; when it genuinely names none that can be pointed at, it is not-yet-actionable, recorded with what's missing, not smuggled in as a vague item. The interpretation is *deliberately open*: freeform feedback is unbounded in shape, so no sentence→defect mapping can be pinned — the four-part bar and the not-yet-actionable escape keep the *output* convergent even though the reading is judged. When the batch arrived via `--from` and the frozen text is genuinely ambiguous between two concrete defects (no maintainer present to clarify), do not pick one silently: record both readings and route the choice to the maintainer, or mark it not-yet-actionable — never guess which of two real items was meant.

## Provenance and the empty case

`--from=<ref>` seeds the batch from a source file (a report or notes); absent it, interrogate the maintainer for the change-request and freeform shapes inline before proceeding. If the batch is **empty** — no source, nothing offered, or every candidate demoted to not-yet-actionable — report that there is nothing to act on and stop; an empty worklist is a valid outcome, not an error, and revise does not go hunting for work the batch didn't contain.
