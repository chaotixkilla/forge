# Deliver at the reader's register

Every praxis skill ends by handing a person the thing it produced, and nearly every one of them pins that deliverable's *content* in detail — the fields, the verdicts, the ordering, the none-cases — while pinning how it *reads* not at all. The gap is not theoretical: across the plugin's terminal phases, content is specified exhaustively and register is specified almost nowhere, so each run fills it from the only vocabulary it has to hand, which is the run's own machinery. That produces the failure this rule exists to stop — reports that are complete, accurate, and unreadable: house jargon the reader never asked to learn, every field padded to a paragraph because nothing said not to, and a last line that records the outcome without ever saying what the reader is now supposed to do. This rule is the binding a terminal phase applies; each obligation below is *owned* by another rule and defined there, never redefined here.

## The four obligations of a terminal report

- **Lead with the conclusion, not the chronology** — what was established, before how the run got there ([lead-with-the-takeaway](lead-with-the-takeaway.md)).
- **Say what the reader must now do** ([make-the-ask-explicit](make-the-ask-explicit.md)). A run that hands over a result and no ask leaves the reader to infer whether anything is owed. This includes the **nothing-owed** case: "no action needed" is an ask, stated, and its absence reads identically to an ask that was forgotten.
- **Speak the reader's vocabulary, not the run's** ([match-reader-vocabulary](match-reader-vocabulary.md)). Phase names, internal ordinals, grade codes, agent and critic names, and the machinery nouns a procedure needed to reach its result are *how the answer was produced*; they are not the answer. The reader will never use them again.
- **Size the detail to the artifact's class** ([right-size-the-detail](right-size-the-detail.md)), by the fork below rather than by instinct.

**Bind only what the phase does not already pin.** Several terminal phases already settle one or two of these on their own — a headline computed rather than composed, a pinned field order that leads with the verdict, a scannable severity glyph. Where a phase already carries an obligation, adding a citation for it buys nothing and costs every run the read. Bind the gaps.

## Economy is never bought with honesty

The dangerous misreading of "size the detail" is a tightening pass aimed at the parts that make a report trustworthy, because those parts *look* like padding and are the easiest to cut. They are content. None of the following is ever removed to shorten a report:

- **A stated unknown** — what the run could not reach, did not establish, or deliberately left out. A gap named is honest scope; a gap omitted reads as *covered*, which is a different claim and a false one.
- **A divergence** — two sources that disagree, reported as disagreeing. Silently reconciling them to save a sentence destroys the one fact the reader most needed.
- **A load-bearing hedge** — where the *strength* of a claim is itself the finding. Directness is a property of structure, not a licence to state a provisional result as a settled one.
- **An explicit none-case** — a field or section whose emptiness is stated. A missing field and an empty one read identically, and only one of them is honest.
- **A named level or verdict value the skill pins** — a graded rung, a verdict name, a fixed status string the skill defines and reports on. Paraphrasing one merges outcomes the scale exists to separate, so these **outrank** the plain-language obligation above *whether or not the skill separately forbids paraphrasing them* — being pinned and reported on is the whole trigger. Translate the machinery *around* such a value; never the value itself.

`(basis: derived — each item is a case where the maintainer-facing complaint that praxis is too verbose and the requirement that praxis be honest pull in opposite directions, and the resolution is the same every time: verbosity is words spent on what the reader already knows, never words spent on what the run does not know. Pinned as a list because a general instruction to be concise reliably strips exactly these first — they are the passages that read as hedging, throat-clearing, or repetition to anyone not checking whether the claim is true.)`

## The guidance / reference fork decides how hard to cut

[right-size-the-detail](right-size-the-detail.md) carries a fork it explicitly refuses to collapse: a **guidance** artifact minimizes and defers, a **reference** artifact is complete and exhaustive, and neither default is universally right. Which side a terminal report sits on is a classification, not a preference, and getting it wrong fails in a specific direction — a reference deliverable tightened as though it were guidance drops a fact some reader needed, and drops it silently.

Classify before cutting. Where one deliverable genuinely contains both — a scannable headline and per-item verdicts over a dossier whose field list is fixed by what a downstream consumer requires — **split the classification rather than averaging it**: minimize the part a person reads to decide, keep complete the part a person reads to act. Averaging produces the worst of both, a headline too long to scan above a dossier too thin to use.

`(basis: derived — the fork is right-size-the-detail's own, ratified there; what this rule adds is that a *terminal report* is where the misclassification actually bites, because a run under instruction to be concise has no reason to stop and ask which kind of artifact it is holding, and the two failure modes are asymmetric — an over-long guidance report wastes a reader's minute, an over-cut reference report loses a fact nobody knows is missing.)`
