The framed question can be answered by many possible experiments, and they are not equal: the right one is the smallest experiment that still produces a *trustworthy* signal on the exact unknown. Two failure modes bracket this choice. Over-build — a probe with error handling, structure, and polish — and you've spent the spike's budget on code you're about to throw away. Under-build — a probe so minimal it stubs the very thing in doubt — and you get a fast, cheap signal that answers nothing (a guaranteed *still-open*). This phase picks the probe that sits between them.

## The cheapest-probe selection basis

Choose the probe that reaches a trustworthy pass/fail signal on the framed unknown for the least build effort. **"Cheapest" means least effort to a *trustworthy* signal — not least code in the absolute, and not fastest to *any* signal.** A probe is a candidate only if it actually exercises the framed unknown; among those, cheaper wins. Order candidates by these discriminators, in priority:

1. **Exercises the real risk (a gate, not a preference).** The probe must run the actual thing in doubt under conditions faithful to the question — never a stub, mock, or toy substitute *of the unknown itself* (stubbing everything *else* is not just allowed but required — see below). A probe that fakes the thing under test is disqualified no matter how cheap: it can only ever return *still-open* ([verdict-scale](../rules/verdict-scale.md)). This is the failure mode the phase exists to catch — the cheapest probe to *build* is often the one that dodges the risk, and it is worthless. `(basis: a stub replaces a collaborator, never the subject under test — replacing the component whose behavior *is* the open question is a category error that measures the stand-in, not reality: Meszaros, *xUnit Test Patterns*; "don't mock what you don't own," GOOS ch.8 (Freeman & Pryce) — a double encodes *your* assumption about the uncertain component, so a green result confirms the assumption, not the world; the observable symptom is a run that "passes green but masks errors," Fowler, *Mocks Aren't Stubs*. The crisp "stubbing the thing under test" anti-pattern, scoped to spikes, is a house synthesis of these unit-testing authorities plus the controlled-experiment rule below — no single source names it for spikes.)`
2. **Isolates the single unknown.** Among probes that clear the gate, prefer the one that varies only the framed unknown and stubs, mocks, or hardcodes everything else ([isolate-what-you-test](../rules/isolate-what-you-test.md)) — fewer confounds means a signal you can actually attribute. `(basis: the controlled-experiment rule — vary one factor, hold the rest fixed; a probe that changes several things at once cannot attribute the outcome — Zeller, delta debugging / *Why Programs Fail*.)`
3. **Reaches a clear signal fastest.** Prefer the probe with the shortest path to an unambiguous pass/fail ([make-failure-fast-and-loud](../rules/make-failure-fast-and-loud.md)) over one that needs more scaffolding to read.
4. **Reuses scouted prior art over fresh build.** Prefer seeding from what [scout-prior-art](02-scout-prior-art.md) found — a reference implementation, an example, a library's own test — over writing from scratch ([favor-disposability](../rules/favor-disposability.md): borrow throwaway code rather than craft it).

Tie-break when two candidates are otherwise equal: fewer components touched, less code to write. `(basis: ratified by the maintainer, 2026-07-09. "Cheapest = least effort to a trustworthy signal, thin along the right axis, gated on exercising the real risk" — derived from the minimal-experiment tradition: cost is cut on *breadth* (features, polish, final architecture), never on the thing under question, which is exercised for real — "the thinnest possible slice of *real* functionality... end-to-end" (Freeman & Pryce, GOOS; Cockburn's walking skeleton); "the simplest thing that could possibly work" is a *question* with a mandatory evaluate-after step, not a bare imperative (Cunningham, artima). Corrected for the spike-specific trap that the absolute-cheapest probe often stubs the very unknown it should test (discriminator 1). No single authority pins the discriminator order, so it is the maintainer's ratified house standard.)`

## Under `--max-agents` — pick N candidate approaches

When racing is enabled, this phase selects not one probe but up to *n* candidate *approaches* to the same question — each a **distinct mechanism or strategy**, not the same approach re-parameterized (the axis of difference is pinned in [parallel-fan-out](../modules/parallel-fan-out.md); a parameter sweep is one approach, not a race). Each still obeys the basis above (each must exercise the real risk). How they are compared and selected is [parallel-fan-out](../modules/parallel-fan-out.md).

The output of this phase: the chosen probe (or the N candidate approaches), stated as *what it will exercise* and *what it will stub* — the build plan [build-the-spike](04-build-the-spike.md) executes.
