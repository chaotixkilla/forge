    --to=<target>: override the destination within the space (a path or a page id)

    --draft: publish in a non-final draft state for review before going live

    - key: tools.artifacts

Usage & examples — when to reach for this skill, and concrete flag invocations: see [usage.md](usage.md).

A thin port over the artifacts backend: it names the capability, and the configured backend's adapter holds the concrete calls. A caller hands it a finished artifact — authored content organized into sections.

**Contract — clean export, published faithfully.** An artifact is a clean export of the session's *substance* for a human audience: it renders the content and the decisions, never the machinery — no internal tool calls, no agent/phase/skill mechanics, no praxis process, no account of how it was produced. The split is owned on both sides and neither half is optional: the *producing* skill strips every internal-process reference before it hands the tree over; **this** skill publishes what it is given faithfully — it does not re-author, edit, scrub, or validate the content, and it adds **no** process metadata of its own (no "generated by / authored via praxis" footer, no run log, no phase/agent/tool trace, no branding). `(basis: maintainer, 2026-07-03; "artifacts are team-facing documents")`

1. Resolve the target. Read `tools.artifacts`: its own provider, transport, `secret_ref` and `destination` are the **home**, where praxis publishes by default, and `audiences` lists named **audience spaces**, each with its own provider, transport, `secret_ref` and `destination`. `--space=<name>` selects the audience space of that name, and without it the space is the home; a name no space carries is rejected up front. An older config's per-type `destinations` map is read for its `default` entry alone, as the home's `destination` `(basis: maintainer, 2026-10-01)`, and only when `destination` is empty `(basis: derived — the current key outranks the older one, as the edit guard reads them)`. Note an advisory for each config entry read this way or ignored: the `destinations` map (its `default` read as the destination, or ignored under a set one, and each type entry ignored by name), and any key outside the current shape — `provider`, `transport`, `secret_ref`, `destination`, `task_log` and `audiences` on the slot; `name`, `provider`, `transport`, `secret_ref`, `destination` and `for` on a space. Each names the entry and points to `init:artifacts` to rewrite the slot. `(basis: maintainer, 2026-10-02)` Then resolve the destination within the space by the precedence in [stable-identity-and-precedence](rules/stable-identity-and-precedence.md) — unless the space's adapter declares that it places artifacts without one, which skips the lookup and the ask below. If the destination is empty **and** no override was given, do **not** invent or silently pick a destination — **ask the user where in that space to publish** this artifact (name it and the space) and use their answer as a one-shot `--to` for this publish. When the run calling this publish asks nothing after its start ([ask-while-the-user-is-here](../gather/rules/ask-while-the-user-is-here.md)), don't ask: report `unavailable`, as [stable-identity-and-precedence](rules/stable-identity-and-precedence.md) says, and let the caller degrade. Reject a contradictory invocation (e.g. `--idempotent` with `--version`) up front.
2. Take the page tree the caller shaped, and check it is portable: one main page with ordered subpages, content as backend-neutral sections. A caller that hands over loose content gets it back as `unsupported-content` ([failure-taxonomy](rules/failure-taxonomy.md)), never a tree carved here.
3. Map the tree to the backend's page model (nested pages, or an index plus section files); where a block cannot be represented, degrade it by [degrade-unsupported-content](rules/degrade-unsupported-content.md) rather than dropping or erroring silently.
4. Dispatch to the adapter for the resolved space's provider, handing it that space's transport and `secret_ref` and the destination resolved in step 1 — the adapter does not re-derive it: the concrete backend calls live in adapters/&lt;backend&gt;. A provider with no adapter there is `unavailable`. Create parents before children, in tree order.
5. Return the published location to the caller — links/paths to the main page and every subpage, in tree order, with the main page's [reach](#reach), plus any advisories that accompany a successful publish (an older-config entry from step 1, which comes back with a failure too, an ignored `--dest-dir`, a degraded block) — or a capability-level failure the caller can react to, from [failure-taxonomy](rules/failure-taxonomy.md), never a raw provider error.

## Fetch a published artifact

Given a location a publish returned — the main page's link, path or recorded id — and the space it was published to (the home unless the caller names an audience space), resolve the space as step 1 does, advisories included, and read the tree back through that space's adapter: the main page and each subpage in tree order, with its content and its location. This is how a caller reads back what it published, such as a resumed task reading its documentation, on whichever backend holds it. A location that resolves to nothing is `target-not-found`, an unreachable backend `unavailable` ([failure-taxonomy](rules/failure-taxonomy.md)); never fall back to a different page with a similar title.

## Reach

Every publish, a partial one included, returns one reach, for its main location, the one a caller links: who can open it right after the publish, with no one changing its access. It is exactly one of: `(basis: maintainer, 2026-10-02)`

- **`open`** — accounts other than the publisher's can open the link as-is, through the access the place it landed already grants (a shared parent, a team space). It says others can open it, not that a given reader can.
- **`private-until-shared`** — only the publisher's account can open it until its owner shares it. It comes back with the adapter's one line on how the owner shares it by hand, for the caller to put to the user. The port shares nothing itself.
- **`local-only`** — a path on the publisher's machine, which no one else can open however it is shared.

Each adapter states which reach its backend yields and how it tells. One that can't tell `open` from `private-until-shared` reports `private-until-shared`, since a false `open` hands readers a dead link and a false `private-until-shared` costs the user one question. `(basis: derived from that cost asymmetry)`

## Retire a superseded document

Given a document's main-page location, its space, and the location of the document that supersedes it in the same space, such as a unit's consolidated record replacing its older per-round records, remove the superseded document through that space's adapter. Whether to retire, and the user's consent, are the caller's; the port retires only the location it is handed, and the whole document under it. A subpage leaves a tree through an `--idempotent` republish without it, never through a retire. `(basis: maintainer, 2026-10-02)`

1. Resolve the space as step 1 does, advisories included.
2. Reject a superseding location that is the retired one, up front. Then fetch the superseding location; unless its whole tree comes back, retire nothing and return that fetch's outcome, naming the superseding location. `(basis: derived — a retire can't be undone on every backend, so the replacement is confirmed first)`
3. Dispatch the retire to the space's adapter, which removes the document as its **Retire** section says.
4. Return the retired location and what retiring left behind, as the adapter states it, or an outcome from [failure-taxonomy](rules/failure-taxonomy.md).

Under `--dry-run`, run steps 1–2 and return what would be removed and what would be left behind, retiring nothing. Report the removal as permitted only where the adapter's Retire section names a permission check it can run ahead of the retire; otherwise report its permission as unchecked, since the real retire can still come back `unauthorized`. `(basis: derived from backends whose removal permission no read shows)`

## Flag behaviors

- **`--space`** selects an audience space instead of the home (step 1), for a publish, a fetch or a retire.
- **`--to` / `--dest-dir`** override where in the space the artifact lands (a path or a page id; a file-backed base directory). They resolve against the config default by the precedence in [stable-identity-and-precedence](rules/stable-identity-and-precedence.md).
- **`--draft`** publishes in the backend's non-final/unlisted state. If the backend has no draft concept, report `unsupported-content` (per [failure-taxonomy](rules/failure-taxonomy.md)) rather than silently publishing live — each adapter declares its draft support.
- **`--version`** writes a new labeled copy alongside prior outputs, preserving history, resolving the prior by the same stable identity ([stable-identity-and-precedence](rules/stable-identity-and-precedence.md)). Mutually exclusive with `--idempotent`.
- **`--idempotent`** matches the already-published artifact by stable identity and updates it in place. If identity cannot be resolved reliably, fail `conflict` rather than mint a duplicate — see [stable-identity-and-precedence](rules/stable-identity-and-precedence.md).
- **`--dry-run`** writes nothing. A publish runs steps 1–3 and returns the resolved target and the tree that would be published, so an override can be checked before it writes; a retire runs as its section says; a fetch writes nothing, so it runs as it would without the flag.
