Usage & examples — when to reach for this skill, and concrete flag invocations: see [usage.md](usage.md).

A thin port over the artifacts backend: it names the capability, and the configured backend's adapter holds the concrete calls. A caller hands it a finished artifact — authored content organized into sections.

**Contract — clean export, published faithfully.** An artifact is a clean export of the session's *substance* for a human audience: it renders the content and the decisions, never the machinery — no internal tool calls, no agent/phase/skill mechanics, no praxis process, no account of how it was produced. The split is owned on both sides and neither half is optional: the *producing* skill strips every internal-process reference before it hands the tree over; **this** skill publishes what it is given faithfully — it does not re-author, edit, scrub, or validate the content, and it adds **no** process metadata of its own (no "generated by / authored via praxis" footer, no run log, no phase/agent/tool trace, no branding). `(basis: maintainer, 2026-07-03; "artifacts are team-facing documents")`

1. Resolve the target. Read `tools.artifacts`: its own provider, transport, `secret_ref` and `destination` are the **home**, where praxis publishes by default, and `audiences` lists named **audience spaces**, each with its own provider, transport, `secret_ref` and `destination`. `--space=<name>` selects the audience space of that name, and without it the space is the home; a name no space carries is rejected up front. An older config's per-type `destinations` map reads its `default` entry as the home's `destination`, and its type entries are ignored. `(basis: maintainer, 2026-10-01)` Then resolve the destination within the space by the precedence in [stable-identity-and-precedence](rules/stable-identity-and-precedence.md) — unless the space's adapter declares that it places artifacts without one, which skips the lookup and the ask below. If the destination is empty **and** no override was given, do **not** invent or silently pick a destination — **ask the user where in that space to publish** this artifact (name it and the space) and use their answer as a one-shot `--to` for this publish. When the run calling this publish asks nothing after its start ([ask-while-the-user-is-here](../gather/rules/ask-while-the-user-is-here.md)), don't ask: report `unavailable`, as [stable-identity-and-precedence](rules/stable-identity-and-precedence.md) says, and let the caller degrade. Reject a contradictory invocation (e.g. `--idempotent` with `--version`) up front.
2. Take the page tree the caller shaped, and check it is portable: one main page with ordered subpages, content as backend-neutral sections. A caller that hands over loose content gets it back as `unsupported-content` ([failure-taxonomy](rules/failure-taxonomy.md)), never a tree carved here.
3. Map the tree to the backend's page model (nested pages, or an index plus section files); where a block cannot be represented, degrade it by [degrade-unsupported-content](rules/degrade-unsupported-content.md) rather than dropping or erroring silently.
4. Dispatch to the adapter for the resolved space's provider, handing it that space's transport and `secret_ref` and the destination resolved in step 1 — the adapter does not re-derive it: the concrete backend calls live in adapters/&lt;backend&gt;. A provider with no adapter there is `unavailable`. Create parents before children, in tree order.
5. Return the published location to the caller — links/paths to the main page and every subpage, in tree order, plus any advisories that accompany a successful publish (e.g. an ignored `--dest-dir`, a degraded block) — or a capability-level failure the caller can react to, from [failure-taxonomy](rules/failure-taxonomy.md), never a raw provider error.

## Fetch a published artifact

Given a location a publish returned — the main page's link, path or recorded id — and the space it was published to (the home unless the caller names an audience space), read the tree back through that space's adapter: the main page and each subpage in tree order, with its content and its location. This is how a caller reads back what it published, such as a resumed task reading its documentation, on whichever backend holds it. A location that resolves to nothing is `target-not-found`, an unreachable backend `unavailable` ([failure-taxonomy](rules/failure-taxonomy.md)); never fall back to a different page with a similar title.

## Flag behaviors

- **`--space`** selects an audience space instead of the home (step 1).
- **`--to` / `--dest-dir`** override where in the space the artifact lands (a path or a page id; a file-backed base directory). They resolve against the config default by the precedence in [stable-identity-and-precedence](rules/stable-identity-and-precedence.md).
- **`--draft`** publishes in the backend's non-final/unlisted state. If the backend has no draft concept, report `unsupported-content` (per [failure-taxonomy](rules/failure-taxonomy.md)) rather than silently publishing live — each adapter declares its draft support.
- **`--version`** writes a new labeled copy alongside prior outputs, preserving history, resolving the prior by the same stable identity ([stable-identity-and-precedence](rules/stable-identity-and-precedence.md)). Mutually exclusive with `--idempotent`.
- **`--idempotent`** matches the already-published artifact by stable identity and updates it in place. If identity cannot be resolved reliably, fail `conflict` rather than mint a duplicate — see [stable-identity-and-precedence](rules/stable-identity-and-precedence.md).
- **`--dry-run`** runs resolve → check → map but performs no writes; returns the resolved target and the tree that would be published, so an override can be checked before it writes.
