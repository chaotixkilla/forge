# Spec

The specification a task builds against: what must be true when the work is done, so the plan, the code and the tests can each be checked against it.

## Membership

The spec step's result: its requirements, each with acceptance criteria and its source (a ticket, an RFC, a conversation), the constraints and non-goals, and the questions still open. A changed requirement reopens the spec: within its round, the page is updated with the change, its date and its source marked, not filed again, and its traceability row reopens with it. (basis: maintainer, 2026-09-30) A later round that changes a requirement files its own spec, restated whole. (basis: maintainer, 2026-10-07)
