## Publish the tree

Bring the task record up to date with this filing ([task-record](../rules/types/task-record.md)), the pieces handed over already shaped included: a page joins the documents filed so far, and a section joins its page in the act's row order — a waiting piece's row is in its file name, this filing's in the step key it's handed — with the delivery's after every step's. Then publish the task's whole documentation through [artifacts](../../artifacts/SKILL.md) at the destination the first phase resolved — new on the task's first filing, in place on every later one and on every filing to a file backend (its `--idempotent` publish, with the identity the first phase resolved). Shape it as a portable page tree ([portable-tree-shape](../rules/portable-tree-shape.md)): the task record first, as the main page's landing summary, then one subpage per document, the current round's first and each earlier round's after it, latest first. (basis: derived — the artifacts port has no operation that adds one page beneath another; latest first, maintainer, 2026-10-02) Within a round, pages take the act's row order of the result each came from, a page first filed from `closing.md` after every step's, and several from one result keep the order it holds them in; a folded task's own task record leads its round's pages. (basis: derived from the sections' row order above) Each subpage is titled with its type, and, once the task has more than one round, its round's name in lower case ([task-record](../rules/types/task-record.md)), `Review record · review of a1b2c3d · 2026-10-02`.

Return to the caller each page's location and the task record's location, with the reach the artifacts port returned for it and, when that reach is `private-until-shared`, the port's share line. The task record's location is the link the task's memory entry keeps.

## Degraded and preview

When the artifacts port reports the backend unavailable or fails the publish, hand back to the caller, marked unfiled with the reason, what this filing's own result added, as shaped: each page shaped from it, and each section it adds to another page — its scratchpad section, its entry in the task record's "What was done", the delivery's update to the review record. Never hand back that other page whole, since every filing rebuilds it from what it's handed, nor a piece handed over already shaped, which the caller still holds ([keep-the-act-marker](../../work/rules/keep-the-act-marker.md)). A failure that left the task record's page published, as a `partial` publish can, also returns that location with its reach, as a success would, so the next filing goes there. (basis: derived from how the work orchestrator keeps unfiled results, and from a page backend's location being known only from a publish's return) Under `--dry-run`, run the artifacts port's own `--dry-run` and return what it would publish, and where.

The output is the locations above, or the unfiled pieces, for [mirror-the-task-log](04-mirror-the-task-log.md).
