A result filed into the wrong task, or a second copy of a task's documentation, splits the record the next reader depends on.

## Find it

The caller names the task (`--task=<key>`) and passes its state: the task's memory entry, and every document filed for it so far, in every round, each with its round and the location the last publish or fetch returned for it, a folded earlier task's pages among them ([open-the-task](../../work/phases/02-open-the-task.md)). document rebuilds nothing from the backend. With a step's result it passes the step's key, `<row>:<skill>`, and what it ran for when the act runs it more than once, `unit 2`, or the review requests it covered, `review requests 405, 406`; a finding made outside the steps that changes no step's result comes with none. The caller may also hand over pieces earlier filings shaped but couldn't publish, each labelled with its type and arriving under its unfiled file name ([keep-the-act-marker](../../work/rules/keep-the-act-marker.md)) — `<row>-<skill>.md`, `delivery.md`, `closing.md` or `finding.md`, each piece labelled with its step key or `no step`, and with what it ran for when it came with one; they skip [shape-the-document](02-shape-the-document.md) and file with this filing ([publish-and-link](03-publish-and-link.md)). When the entry links the task's documentation, that's where this filing goes. When it links none, the task has no documentation yet: start it with its task record ([task-record](../rules/types/task-record.md)).

## Where it lives

A task's documentation is one artifact with a destination of its own. It's handed to artifacts as type `task-documentation` and lands in the artifacts home, under the home's destination — read as [artifacts](../../artifacts/SKILL.md) step 1 reads it, older configs included. On a file backend its destination is the directory `tasks/<key>/` under that destination — passed as the artifacts port's base directory (`--dest-dir=<destination>/tasks/<key>/`), since `--to` would replace the destination rather than nest under it — and that path is its identity, so no two tasks collide; on a page backend it's a page titled `<key> · <title>` under the destination, and on a backend that takes no destination, a document of that title. On any backend but a file one, after the first filing its identity is the location the task's entry links: pass that location as the artifacts port's `--to` on every later filing. On a file backend the path is known before anything lands, so every filing, the first included, publishes in place: a tree a failed first filing left there is rewritten, never refused as a conflict. (basis: derived from the artifacts port's stable-identity rule, under which a file backend's path is its identity and a page backend's id is known only once a publish returns it)

When the home is a file backend inside the repository, the task's documentation sits in the working tree, so it is kept out of the work: it's never part of a change any step judges, tests or commits — a step's window and develop's clean-tree check leave its directory out — and it reaches version control only in its own commit, which the act opening a review request makes on the task's branch just before linking it ([open-the-review-request](../../work/rules/open-the-review-request.md)); without a review request, committing it is left to the user. (routed to maintainer: committed separately when a review request links it, else left to the user, since documentation committed with the change would enter the window every step judges.)

## Refuse a round that has ended

A filing goes to the latest round the entry it's handed names. Read the task's entry as the memory holds it: when that names a later round, or its status is closed, the filing's round has ended and takes no more filings ([pages-belong-to-their-task](../rules/pages-belong-to-their-task.md)); say so and stop. The memory turns an entry closed only once the filing that closes it lands ([close-out](../../work/phases/04-close-out.md)), so that filing is taken.

The output is where the task's documentation is, or will be, and its task record as it stands, for [shape-the-document](02-shape-the-document.md).
