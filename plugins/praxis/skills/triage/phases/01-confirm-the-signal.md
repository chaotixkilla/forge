Everything downstream — how hard the response mitigates, how often it communicates, what "resolved" will require — keys off two judgments triage makes: *is this a real incident at all?* and *how bad is it?* This phase makes the first.

## Establish the signal — confirm it is real before responding

Pull the current picture before reacting to the alarm. Read the firing signal — the one `--from-telemetry=<ref>` names, when it's given — and its surrounding context through the [telemetry](../../telemetry/SKILL.md) port — the metric's onset, rate, affected scope, and correlated signals — and recruit the [repository explorer](../../../agents/explorers/repository.md) for what changed recently near the symptom. Without fan-out, read the signal through the port and inspect recent history yourself before proceeding. Recruit only as [fan-out-only-when-it-pays](../../gather/rules/fan-out-only-when-it-pays.md) allows.

Then apply [real-signal-vs-flapping](../rules/real-signal-vs-flapping.md)'s ordered tests, which land the signal at engage, stand down, or investigate. **Engage** is a real incident. **Stand down** is noise: record it, flag the noisy alert for tuning in the returned result (filing a tuning item is the caller's), and end the run at *stood-down*. A real signal with no user-facing symptom ends at *investigate*. [scope-and-grade](02-scope-and-grade.md) holds the outcomes.

When a `--from-incident` seed ([from-incident](../modules/from-incident.md)) is in play, its intake has already pulled the reported symptom — fold it in here, but treat the report as a *claim to reconcile* against what the live signal actually shows, not ground truth — and the gap between reported and observed is itself evidence.

## Degrade and done-state

- **Degrade — telemetry unavailable.** triage cannot run blind. A `--from-telemetry` reference is read through the same port, so with telemetry unavailable it yields nothing and is no seed. If no incident was seeded either, halt and report that telemetry is unavailable — the telemetry port guides its own setup. If an incident *was* seeded (`--from-incident`), proceed from it, and grade the scope it reports `unverified` ([results-and-certainty](../../../craft/evidence/results-and-certainty.md)): it rests on the record's word, with no live signal read. A read that comes back **not collected** is a blind read, treated the same way — it confirms nothing about the system. One that comes back **empty** for the named signal is a reading: the signal isn't firing now, which is stand-down evidence unless a seeded symptom is still live. `(basis: derived from the reference being readable only through the unavailable port)`
- **Done-state.** Either a real incident — go on to [scope-and-grade](02-scope-and-grade.md) — or a *stood-down* result with the reason and the noisy alert flagged for tuning, which ends the run.
