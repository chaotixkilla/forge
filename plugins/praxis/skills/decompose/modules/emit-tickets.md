# emit-tickets (`--ticket`)

Activated by `--ticket`, referenced from [check-coverage-and-handoff](../phases/05-check-coverage-and-handoff.md).

The base run ends at `--plan-only` — the decomposition presented for review, no external side effect. This module changes *where the units land*: instead of presenting them, record them as tracked work-items in the project's tracker, one item per unit, carrying each unit's dependencies and sequence. Deletion test: remove this module and decompose still produces and presents the decomposition; emitting to a tracker is genuinely optional, which is why it is a module and not part of the handoff phase.

## The delta — render each unit as a work-item

Hand the covered, ordered unit set to the **project_mgmt capability's `create work-items` operation** (served by the [project-mgmt](../../project-mgmt/SKILL.md) skill, which dispatches to whichever provider is configured). Per unit, supply:

- **Title** — the unit's single outcome, stated as its done-condition names it ([one-unit-one-outcome](../rules/one-unit-one-outcome.md)).
- **Body** — the unit's scope, its one-sentence done-condition/acceptance criteria, and its just-enough context with the link back to the source ([carry-just-enough-context](../rules/carry-just-enough-context.md)).
- **Dependency links** — each cross-unit prerequisite as a relation to the item it depends on ([make-dependencies-explicit](../rules/make-dependencies-explicit.md)); the capability maps these to the provider's relation mechanism and returns the per-unit outcome (created / created-but-link-unset / not-created) so unset links can be completed without re-creating items.
- **Sequence** — the dependency-then-risk order from [size-and-sequence](../phases/03-size-and-sequence.md), carried as the provider's order field.

## Rendered labels — what carries a scale, and what does not

Three label classes could ride on a work-item; each is pinned so a bare label never ships:

- **Size — no grade is rendered.** By the time units reach emit they are all *right-sized* (the too-big were split, the trivial merged, in [size-and-sequence](../phases/03-size-and-sequence.md)), so a size label would read "right-sized" on every item — noise, not signal. decompose therefore mints **no** size grade onto the ticket. `(basis: the unit-size verdict ([unit-size-scale](../rules/unit-size-scale.md)) governs the internal carve, not the output; emitting it post-sizing carries no information. If a team wants relative estimates on items, that is a tracker-field concern for a future flag, not a scale decompose invents here — ratified by the maintainer, 2026-07-10.)`
- **Priority — relayed from the source in full, never minted, never mapped here.** decompose does not assign priority; where the source carries one (spec's MoSCoW rungs, or a plan unit's inherited priority), relay it **faithfully and in full** — hand the source's *complete* vocabulary (MoSCoW: **Must / Should / Could / Won't** — all four) to the project_mgmt capability as the unit's priority. decompose does **not** map those rungs onto the provider's priority field, collapse them, or reason about how many levels that field has: that normalization is **adapter-domain, below the seam**, where the configured provider's field shape is actually known. Where the provider's field cannot represent a rung (fewer levels, no matching option), the capability reports it per unit in capability terms and decompose surfaces that to the caller — it never silently coerces a rung at the skill layer. Where the source carries **no** priority, render none — do not invent one. `(basis: decompose is downstream of prioritization (spec owns MoSCoW; plan inherits it), so it *relays* a graded label — the standard-closure relayed-vocabulary trigger obliges reproducing the source's full defined vocabulary, which decompose satisfies by handing all four rungs down intact rather than dropping or collapsing any at the skill layer. The rung→provider-field mapping is the adapter's job by the ports-and-adapters seam and the project-mgmt port's own contract ("records the items it is handed"; "the caller never learns a provider's vocabulary"; "provider coverage is by adapter") — decompose delegates --ticket wholesale and holds no provider knowledge (ratified 2026-07-10), so it must not branch on field cardinality. Maps to spec's ratified MoSCoW scale.)`
- **Risk — a spike flag, not a graded scale.** A unit that is a timeboxed investigation ([size-the-unknowns-as-spikes](../rules/size-the-unknowns-as-spikes.md)) is flagged as a spike (a boolean marker / label the tracker supports), and its body states the question and time box. decompose renders no graded "risk level" — risk enters the decomposition as the sequencing pass and the spike carve, neither of which is a rated label. `(basis: risk is handled as sequence position and the spike/normal-unit split, not as a rung ladder; a graded risk scale would be an undefined scale with no source — deliberately not minted.)`

## Prerequisite and degrade

`--ticket` is the reason decompose reaches the project_mgmt capability at all. decompose itself declares **no** project_mgmt prerequisite — the [project-mgmt](../../project-mgmt/SKILL.md) skill owns `tools.project_mgmt` (doer-owns-prerequisites), and decompose's base path is ambient, running without any configured backend. Invoke the capability; if it reports the backend unavailable (`tools.project_mgmt` unconfigured — the `project-mgmt` skill owns guiding the user through `init:project_mgmt`), **degrade rather than block**: fall back to [emit-checklist](emit-checklist.md) (or, failing that, `--plan-only`), and tell the caller plainly that the tracker could not be reached and what was emitted instead. Do not silently drop the decomposition. `(basis: decompose's degrade-not-block posture on a missing tracker is ratified by the maintainer, 2026-07-10 — it has a meaningful fallback (checklist/plan-only), so it catches the capability's unavailable signal on its own side, exactly as the project-mgmt skill's usage prescribes; the port itself blocks.)`

The capability reports per-unit outcomes in capability terms (created, created-with-unset-links to complete, or not-created with a cause the caller can act on) — surface those to the caller so a partial emit is completed or retried, never re-created wholesale.
