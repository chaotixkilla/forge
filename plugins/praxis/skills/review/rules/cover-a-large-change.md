# Cover a large change

A small change is covered by one pass. A large one — many files spanning several subsystems — is not: attention thins across the surface, whole areas go unreviewed, and two reviewers reading the same big diff linearly cover *different* subsets, so their finding sets diverge and neither is complete. The effort dial's fan-out (the adversary and simplicity-hawk critics, the explorers) attacks the *whole* change through one lens each — it deepens a pass, it does not **partition the surface** so every part is reached. This rule is the method for covering a large change with breadth, and for proving the breadth was achieved rather than assumed. It is cited from [hunt-for-defects](../phases/03-hunt-for-defects.md), [assess-craft](../phases/04-assess-craft.md), and [triage-and-rank](../phases/05-triage-and-rank.md).

## When to partition

Partition when the change's **surface** exceeds what one pass can hold at the effort's depth: many files across distinct subsystems, layers, or feature slices — not a focused change to a few files. The trigger is *breadth of surface*, not raw line count — a 900-line reformat is one narrow thing (and is set aside as churn anyway, per [scope-the-review](../phases/01-scope-the-review.md)); a 15-file change touching four modules is broad. When the change is small enough for one pass to hold, do not partition — the machinery below is overhead that earns nothing. (Judgment call; state the partition you chose, or that you reviewed the change whole, in the scope line — so a second run can see the breadth decision, not guess it.)

## Partition → review in parallel → merge

- **Partition** the in-scope files into cohesive units — a module, a layer, a feature slice a reviewer can hold at once. The units are disjoint and together cover *every* in-scope file (a file assigned to no unit is a coverage hole waiting to happen).
- **Review each unit independently.** At `--effort=high`/`max`, recruit a reviewer per unit in parallel — each runs the correctness hunt and craft passes over its unit at the effort's depth. Without fan-out, take the units in sequence, one focused pass each. This is **breadth across the surface**, orthogonal to two things it must not be confused with: the *depth per symbol* the blast-radius method and the effort depth row govern ([read-the-diff-in-its-blast-radius](read-the-diff-in-its-blast-radius.md)), and the *whole-change lens* fan-out (adversary, simplicity-hawk), which still runs once over the merged candidate set, not per unit.
- **Merge in triage.** Pool the units' candidates and **dedupe**: a defect on the seam between two units surfaces from both — it is one finding with its locations, not two ([weight-by-impact-not-count](weight-by-impact-not-count.md)). Cross-unit invariants (an assumption two units both lean on) are checked here, where the whole change is back in one view.

This is **not** [decompose](../../decompose/SKILL.md): decompose splits a *design* into independently-shippable work units; this splits a *review's surface* for coverage, and the partition is thrown away when the review completes. Keep the concern in review — it is a coverage method, not a delivery unit.

## The coverage checkpoint

Before delivering the verdict, confirm **every in-scope file was actually reviewed**. Walk the in-scope set that [scope-the-review](../phases/01-scope-the-review.md) settled on against the files the passes (or the parallel units) covered, and account for each: *reviewed*, or *set aside with its stated reason* (generated, vendored, churn). A file that is neither is a coverage hole — review it before the verdict, do not ship a report that is silent about a file no pass ever opened. Silence about a file you reviewed and found clean is a real verdict; silence about a file you never read is an unreviewed file masquerading as one. State the coverage in the scope line ([deliver-findings](../phases/06-deliver-findings.md)) so the author sees the whole in-scope set was covered, not a guessed subset.

(basis: derived — the effort dial defines fan-out as whole-change lenses only, and the model-soundness gate lives back in [build-the-mental-model](../phases/02-build-the-mental-model.md), so the procedure covers depth-per-symbol but not *breadth across a large surface* or a dropped subsystem. Partition + a coverage checkpoint make that breadth reproducible and provable — the same discipline the surrounding-code bar and the scope boundary already apply to depth and to exclusion.)
