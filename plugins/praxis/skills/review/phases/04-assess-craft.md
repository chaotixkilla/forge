The craft-side [noise classes](../rules/known-noise-classes.md) (tool-catchable, pedantic, unrelated quality) are withheld here unless their exception holds.

This pass asks a different question — not "how does this break?" but "how does this read, and how will it evolve?" Everything found here is optional-to-fix by definition ([separate-correctness-from-taste](../rules/separate-correctness-from-taste.md)): if you can name an input where the code is wrong, it is a defect and belongs to [hunt-for-defects](03-hunt-for-defects.md), not here.

## Sweep the craft lenses in scope

If you partitioned a large change for the correctness hunt ([cover-a-large-change](../rules/cover-a-large-change.md)), assess craft over the *same* units — the craft pass covers the same surface the hunt did, so no subsystem's form goes unjudged. For the change's form, at the breadth `--rigor` sets and `--lenses` narrows:

- **Reuse** (`reuse`) — the change reimplements something the codebase already provides: an existing helper, a pattern, an abstraction in the same module. The cost is the future edit that now has to happen in two places ([reuse-before-writing](../../../craft/engineering/reuse-before-writing.md); whether two lookalikes are one truth is [dry-vs-incidental-duplication](../../../craft/engineering/dry-vs-incidental-duplication.md)'s test).
- **Simplification** (`simplification`) — accidental complexity that isn't pulling its weight: dead code, a premature abstraction with one caller, speculative generality, nesting that a guard clause would flatten, a layer that only forwards ([avoid-premature-abstraction](../../../craft/engineering/avoid-premature-abstraction.md), [guard-clauses-vs-nesting](../../../craft/engineering/guard-clauses-vs-nesting.md), [shallow-interface-deep-module](../../../craft/engineering/shallow-interface-deep-module.md), [leave-no-debris](../../../craft/engineering/leave-no-debris.md)).
- **Efficiency** (`efficiency`) — needless work: a redundant pass, an allocation in a loop, an N+1 access pattern, repeated computation of an invariant. Weight it by where it sits — a quadratic loop on a hot path is a real finding; off a cold path it is graded by the low-vs-info test in [severity-scale](../rules/severity-scale.md): low when a maintainer pays a real cost there, info when declining it is reasonable.
- **Altitude and consistency** (`altitude`) — naming that misleads about role or intent ([avoid-misleading-names](../../../craft/engineering/avoid-misleading-names.md)), an abstraction pitched too high or too low for its one job ([right-altitude-abstraction](../../../craft/engineering/right-altitude-abstraction.md)), and divergence from the conventions the surrounding code establishes ([match-the-surrounding-code](../../../craft/engineering/match-the-surrounding-code.md)).
- **Comment hygiene** (`comments`) — comments carrying nothing the code does not already say: a line restating the statement beneath it, a description the code has since moved past ([keep-comments-truthful](../../../craft/engineering/keep-comments-truthful.md)), a narrated history of how the change came to be. Judge by the recover-it-from-the-code-alone discriminator that [comment-the-why-not-the-what](../../../craft/engineering/comment-the-why-not-the-what.md) defines, and never by how heavily the file already comments, which is not a convention to match ([match-the-surrounding-code](../../../craft/engineering/match-the-surrounding-code.md)). The cost is a reader misled by a comment that no longer matches, plus every later reader paying to read what the code already told them. The **inverse is a finding only where the why is genuinely unrecoverable** from the code itself: do not manufacture a request for narration, which would invert the lens into the thing it exists to remove.

## Judge against the neighborhood, and suggest the smallest fix

Every craft finding is measured against *this* codebase, not an external ideal ([match-the-surrounding-code](../../../craft/engineering/match-the-surrounding-code.md)). When you propose a fix, propose the least-invasive one that resolves the finding — point at the existing helper, don't design a new abstraction layer ([prefer-the-smaller-suggestion](../rules/prefer-the-smaller-suggestion.md)) — and where the fix is a restructuring, name it as the move it is ([refactoring-catalogue](../../../craft/engineering/refactoring-catalogue.md)): "Extract Function on the totals loop", not "clean this up". Anchor each finding to its `file:line` and its concrete cost — the specific future edit, the specific reader misled — not a vague "this is messy" ([anchor-every-claim](../../../craft/evidence/anchor-every-claim.md)). Tag each with a **certainty** — how sure you are its premise holds: that the existing helper you cite really exists and applies, that the blocks you call duplicates really match, that the simpler form really preserves behavior — placed by the craft premise tests in [calibrate-certainty-to-rigor](../rules/calibrate-certainty-to-rigor.md).

## Recruit a simplicity-hawk at high rigor

At `--rigor=high` or `max`, recruit the **simplicity-hawk critic** — its lens is "what here is not pulling its weight?" ([justify-every-moving-part](../../../craft/engineering/justify-every-moving-part.md)) — handing it [calibrate-certainty-to-rigor](../rules/calibrate-certainty-to-rigor.md), and [severity-scale](../rules/severity-scale.md) for a *provisional* craft-cost read that [triage-and-rank](05-triage-and-rank.md) re-grades so it grades on those rules' own rungs and anchors rather than a ladder of its own, and fold its surviving findings in. Without fan-out, apply that lens yourself: for each new abstraction, indirection, or duplicated block, ask what would be lost by deleting or inlining it, and record the ones that answer "nothing." Watch the boundary case: a craft problem one plausible refactor away from becoming a wrong result is a medium-severity *correctness* footgun, moved back to the correctness pile with the evolution named — not left here as mere style ([separate-correctness-from-taste](../rules/separate-correctness-from-taste.md)).

The output is a set of *candidate* craft findings, each anchored and carrying its cost and certainty — unranked, unvalidated, awaiting [triage-and-rank](05-triage-and-rank.md) alongside the correctness candidates.
