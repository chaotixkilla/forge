# Avoid premature abstraction

The moment this rule governs is the one where, writing the first version of something, you feel the pull to make it general — a config-driven strategy, a plugin seam, a base class — *before any second case exists*, on the reasoning that it'll be cheaper to build the seam now than to retrofit it. The trap: an abstraction built for a caller that doesn't exist is shaped by a guess, and a wrong guess is costlier to unwind than the duplication it was meant to spare — you pay to build it, pay again to route real code through it, and pay a third time to tear out the parts the real requirement never wanted. Left to taste, one builder generalizes on the first hunch and another waits for proof, and the codebase fills with half-used seams. This rule pins the discriminator so two builders converge on when the abstraction is earned.

## The discriminator

An abstraction is **premature when its only justification is a hypothetical future**; it is **earned when a present, named requirement demands it.** Apply at the moment of the pull:

- **Name the requirement out loud.** If the justification is "we *might* need to swap the store later" or "someone *could* want another format" — a future with no ticket, no second caller, no committed need — that is speculation; build the concrete thing and stop. If you can name a requirement that exists *now* — a second real caller, a spec line, a variation the current task must handle — the seam has a job, and *what shape* it should take is then [right-altitude-abstraction](right-altitude-abstraction.md)'s call.
- **Weigh the two costs honestly.** The cost of a *speculative* abstraction is not zero-until-wrong: every layer built for no present caller is dead weight a reader must understand and the next maintainer must route around. Against a **zero-caller** abstraction, prefer the concrete duplicate — it is local, visible, and trivially removed once a real requirement reveals the shape, whereas the speculative layer is entangled and expensive to reverse. (This is only the speculative comparison; *how much* real duplication justifies extracting once a requirement exists is a separate, contested call — see below.)
- **Wait for the requirement, not the guess.** The abstraction's right shape is only visible once a *present* requirement shows which axis actually varies; committing before any real caller exists is designing against evidence you don't have. That is this rule's whole thesis — never build the seam for a caller that doesn't yet exist. Once a real need *does* arrive, *how many* duplicates justify extracting (extract at the second, wait for the third, YAGNI) is the contested extract-early-vs-wait fork, owned and routed by [dry-vs-incidental-duplication](../reuse/dry-vs-incidental-duplication.md) — this rule takes no side in it.

(basis: YAGNI — "You Aren't Gonna Need It," coined by Kent Beck on the XP/C3 project (*Extreme Programming Explained*) and canonically written up at Fowler's *Yagni*: don't build capability for a presumed future need. Sandi Metz, "The Wrong Abstraction" — "duplication is far cheaper than the wrong abstraction," and the wrong abstraction is harder to back out of than duplicated code is to consolidate.)

This rule owns the *timing* — whether to abstract at all *yet*; [right-altitude-abstraction](right-altitude-abstraction.md) then owns the *shape* once a seam is warranted. The contested *how much* duplication justifies extracting — the extract-early-vs-wait fork — is settled in [dry-vs-incidental-duplication](../reuse/dry-vs-incidental-duplication.md); do not re-litigate it here. This rule settles only the un-contested half every position shares: never abstract for a caller that does not yet exist. Telling shared knowledge from lookalike code that happens to repeat is also [dry-vs-incidental-duplication](../reuse/dry-vs-incidental-duplication.md)'s job.

## The anchors

- *Earned:* the task itself requires two real formats today, so a single function parameterized over the format replaces the two bodies — the second caller exists, the varying axis is observed, not guessed.
- *Premature (reject):* a `StorageProvider` interface with one implementation, a factory, and a registry, built because "we may move off this store someday" — no second store is named, no ticket exists. Every layer is deletable and the one real caller reads better inlined. Ship the concrete store; add the seam the day a second store is actually on the roadmap.
