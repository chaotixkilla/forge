When sources disagree, the honest move is to represent the disagreement, not collapse it to one side or split the difference — a blended "sources broadly agree" destroys exactly the information the caller needs to decide. (basis: anvil's authoritative-sources "genuine conflict vs difference in emphasis" test + deep-research's surface-disagreement craft.)

## Is it a real conflict?
1. Run the conflict test before calling anything a conflict: two sources genuinely conflict only when they answer the *same question, at the same scope and version*, such that satisfying one violates the other. Otherwise it is not a conflict — one being stricter (meeting it satisfies both) is **emphasis**; different scope or version is **applicability**; a newer document replacing an older one is **supersession**. Report the relationship, not a manufactured conflict.

## Surface, don't collapse
2. For a genuine conflict, return each position as its own item — who holds it (with tier), what it requires, its basis, and the tradeoff a follower accepts — and locate where the dispute actually lives. Never pick a winner by averaging, and never drop the weaker position to make the conflict disappear.
3. A project-reality-vs-domain-norm divergence — code or repository disagreeing with a spec, the docs, or the literature — is always surfaced as a finding, never reconciled: the caller decides whether the project is wrong or the norm doesn't apply here (composition rule 4 in [sourcing-model](sourcing-model.md)).
