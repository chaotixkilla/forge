Usage & examples — when to reach for this skill, and concrete invocations: see [usage.md](usage.md).

A thin port over the knowledge backends: it names the capability, and each source's provider adapter holds the concrete calls. Callers name the read they need; this skill resolves it to the sources. It reads only — it never writes to a backend. It carries out the read it is handed and returns what came back: it chooses no queries, selects no documents, grades no staleness, merges or ranks nothing across sources, and draws no conclusion from what it reads — those belong to the calling skill.

1. Resolve the sources: read `tools.knowledge.sources` — each a named place the project's knowledge lives, with its provider, transport, `secret_ref`, `root`, and a `note` on what it holds. An older config whose `tools.knowledge` is a single provider/transport/root is one source, named by its provider. No sources — an empty list, or `provider: null` — is the capability unconfigured. A configured capability also reads the **artifacts home**, listed last, as a source named `artifacts-home` when it has a destination (`tools.artifacts.destination`, or an older config's `destinations.default`): the home's provider, transport and `secret_ref`, with that destination as root, since praxis's earlier task documentation is prior art. It is left out when a configured source already covers it: one with that provider and root, or — for a provider whose adapter declares a search that spans its whole space — any configured source of that provider. It answers like any other source, so a home nothing has been published to yet comes back `unavailable` for its missing root, never as an empty space. `(basis: maintainer, 2026-10-01)`
2. Take the requested read and its inputs from the caller — one of: **list the sources** (each source's name and note, read from the config — no backend is reached); **search** (a query, and optionally the source names to search — all sources when none are named — or a subtree within one named source, which confines the search to it; returns ranked references, not full documents); **fetch a document** (a reference, and the source it came from — its content plus the provenance the backend exposes); **list a document's children** (a reference and its source — the immediate child documents in the backend's order, for walking a tree one level at a time). A fetch or children request that names no source — a link found in a document, or handed over by the user — goes to the only source when there is one, else to the first-listed source whose provider the reference's form belongs to, and its provenance names that source as the one it was read through. Deliberately open: a reference's form can't tell which of two same-provider sources holds it without reading, and trying each would fold several reads into one outcome — a caller that knows the source names it. A reference no resolved source's provider can claim is malformed ([outcome-taxonomy](rules/outcome-taxonomy.md)). `(basis: derived from a fetch needing one backend to dispatch to)`
3. Dispatch to each source the read targets, through the adapter for that source's provider — adapters/&lt;provider&gt; holds the concrete calls — handing it that source's root, transport and `secret_ref`. A source's search is confined to its root, so two sources on one backend answer for their own spaces; an adapter whose backend can't confine it says so with the results. Sources are read independently: one source failing never stops the read of another, and a source whose provider has no adapter there is `unavailable`.
4. Return the result per source, each tagged with the source's name: for a search, each source's ranked references; for a fetch, the content plus its provenance; for a children list, the child references in order. Each source's part carries its own outcome from [outcome-taxonomy](rules/outcome-taxonomy.md), never a raw provider error.

**`--dry-run`** runs steps 1–2 and stops: it returns the read that would be dispatched — the operation, its inputs, and each source it would reach — and reads nothing.

**The provenance floor.** Every fetched document carries three fields without exception: its **title**, its **reference** (the durable id or path a caller can re-open it by — never a title, which renames), and **where it was read** — the source's name and the resolved space within it. Three more are best-effort, because backends expose different subsets: **author**, **created**, **last-edited**. A best-effort field the backend does not expose comes back as an explicit *not-exposed*, never omitted and never defaulted — an omission reads as an undated or unattributed document, and a caller grading staleness cannot tell "this backend exposes no dates" from "this document has none." `(basis: derived from what a calling lane needs to anchor a claim a second reader can re-open)`
