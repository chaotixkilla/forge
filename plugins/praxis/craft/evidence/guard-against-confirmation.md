# Guard against confirmation

The failure mode of an investigation isn't too little evidence — it's finding exactly the evidence that confirms the answer you already leaned toward. A search rewards the query you write and an experiment answers the question you ask: a query written to confirm will confirm, and an experiment that only *could* confirm tells you far less than one that *could* refute. So spend deliberate effort trying to *break* the emerging answer.

1. **Look for the counter-case.** For each load-bearing claim, run the check that would surface its refutation: the search for "X considered harmful", "why not X", the failure reports and the negative results, not just "X best practice"; the experiment that could disprove the hypothesis for the least effort. An answer only ever confirmed, never attacked, isn't yet verified — and one whose disproving check fails to disprove it is strengthened, not proven.
2. **Weight disconfirming evidence at least as heavily as confirming.** A credible source or result that contradicts your answer is a finding, not noise to search past: it either corrects the answer or forces you to state the boundary where it stops holding.
3. **Beware the fluent consensus.** Broad agreement can be real corroboration or a widely-copied error, and the tell is independence: if the agreeing sources all trace to one origin, the consensus is one voice amplified, and the disconfirming search matters more, not less.

(basis: Popper's falsifiability criterion; Zeller, Why Programs Fail)
